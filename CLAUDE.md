# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A personal Streamlit app ("Fantasy Football Command Center") for the owner's Sleeper fantasy football leagues. Draft mode builds a Value-Over-Replacement (VOR) draft board from three projection feeds (Sleeper/Rotowire, FantasyPros expert consensus, ESPN) combined per stat by median, rescored with the connected league's own scoring settings, attaches consensus rankings (live ESPN ranks, a committed Matthew Berry snapshot, and the board's own order), syncs picks live from the Sleeper draft room, and grades your picks. Start/Sit mode blends the same three feeds for one NFL week, rescoring with the league's rules, and compares your Sleeper starters to the best legal lineup. Player news comes from Claude with the web-search server tool (no direct scraping).

## Commands

Run everything from the repo root.

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt   # pdfplumber is not pinned; install separately for extract_espn.py
.venv/bin/streamlit run src/draft_app.py                             # the app
.venv/bin/python -m pytest tests -q                                  # unit tests (no network; fixtures in tests/fixtures/)
.venv/bin/python -m pytest tests/test_roster_slots.py -q -k flex     # a single test file / keyword
python src/news.py                   # Claude news pull for a hardcoded player
python src/extract_espn.py [file.pdf]  # regenerates src/espn_rankings.json from an ESPN cheat-sheet PDF
```

Tests live in `tests/` and never hit the network: Sleeper payloads are monkeypatched or loaded from `tests/fixtures/` (real league/draft payloads from the owner's 12-team league, a trimmed projections sample, and a synthetic picks list). `tests/conftest.py` only collects from `tests/`. There is no linter or CI.

For UI-level checks (Streamlit's headless AppTest harness, Playwright screenshots) use the `ui-headless-checks` skill in `.claude/skills/`. Always run headless sessions with `DRAFT_STATE_FILE` and `PROJECTION_LOG_FILE` pointed at a scratch path so they never touch the live app's state. There are no committed AppTest tests yet.

### Secrets

A `.env` at the repo root (see `.env.example`; the real file is gitignored and chmod 600), loaded explicitly by `draft_app.py` via `python-dotenv`. `FANTASYPROS_API_KEY` enables the second projection source (without it the board is Sleeper-only and says so); `ANTHROPIC_API_KEY` powers news and the analyst (`CLAUDE_FAST_MODEL`/`CLAUDE_FAST_EFFORT` for news and top stories, `CLAUDE_ANALYST_MODEL`/`CLAUDE_ANALYST_EFFORT`/`CLAUDE_ANALYST_SEARCH_USES` for Ask the Analyst; defaults in `news.py` are Opus 5 at low and high effort, analyst search off). Never read these anywhere but `os.getenv` at the boundary, and never pass the key itself as a `st.cache_data` argument (`load_fantasypros` reads it inside).

Sleeper needs no credentials: its API is public and read-only. The connected league is persisted to `.sleeper_league.json` at the repo root (gitignored) and auto-loaded on startup.

Nothing reads `st.secrets`. The draft board works with no `.env` at all because `news` is imported lazily inside a cached function in `draft_app.py`. `news.py` constructs `Anthropic()` at import time, so the news and analyst buttons catch and display the failure rather than crash.

## Architecture

`src/draft_app.py` is the entry point and holds all UI, CSS, and Streamlit session state. Modules import each other by bare name (`from draft_board import ...`), which only works because Streamlit puts `src/` on `sys.path`.

League config resolution happens at the top of `draft_app.py`, before the board loads: if `st.session_state.league` is set (a dict from `sleeper_league.league_config`), `starters`, `bench_spots`, `num_teams`, and `scoring_settings` come from it and the manual scoring/league-size radios are hidden; otherwise `DEFAULT_STARTERS` and the radios apply. Everything downstream reads those resolved locals, never the constants.

Draft board pipeline, in order:

1. `draft_board.fetch_position` pulls Sleeper projections per position. `extra_sources` is `{source_name: {match_key: stats}}` for the other feeds: `fantasypros.fetch_all` (stat names mapped to Sleeper's via `STAT_MAP`) and `espn_projections.fetch_all` (ESPN's numeric stat ids mapped via `STAT_IDS`; also returns live ESPN ranks and ADP). `blend_stats` combines the lines key by key: median of 3+, mean of 2, pass-through of 1 (Sleeper's `gp` is copied onto lines that lack it because the bonus estimate needs it). Players are joined across feeds by `espn_ranks.match_key`, which is the normalized name except for defenses, which match on nickname ("Texans D/ST" = "Houston Texans"). With `scoring_settings` the blended line is rescored via `scoring.score_stats`, which also adds `estimate_threshold_bonuses` (expected 100/200-yard-game bonuses from season totals, a normal approximation; the 40+/50+ yard TD bonuses are the one thing not covered, see `unprojected_bonus_keys`). Without settings it uses the preset total (`pts_ppr` etc). K and DEF always keep each site's preset total because their stat projections are too sparse (`scoring.PRESET_FALLBACK_POSITIONS`), so never compare K/DEF numbers across sources (`sources_disagree` in the app skips them). Each player carries `points` (the blend), `points_by_source` (`{"sleeper": x, "fp": y, "espn": z}`, only the feeds that scored the player above zero), `sources` (count), Sleeper's `injury_status` / `injury_body_part` / `injury_notes` / `news_updated` (the app renders `status_badge` and `news_badge` from these), and `sleeper_updated_at`. Players under `MIN_POINTS` are dropped. `adp` comes from the Sleeper ADP column matching the league's reception scoring (`adp_key_for`). In Aug 2026, 149 of the top 150 players had all three feeds.
2. `add_value_over_replacement` subtracts the replacement-level player's points. `replacement_ranks(num_teams, starters)` derives the level from the actual slots, splitting flex demand across positions via `FLEX_SHARES` (one FLEX in a 12-team league gives RB/WR = 30, the same as the old `num_teams * 2 + 6` heuristic, which remains the fallback when no starters are passed).
3. `assign_tiers` sets a within-position `tier` by clustering projected points inside the position's `DRAFTABLE_POOL` (`tiers.cluster_tiers`, exact Jenks natural breaks, about one tier per 5 players; everyone past the pool shares a trailing tier). `build_board` does the same on VOR for the top `GLOBAL_POOL` (168) to get `global_tier`, then attaches bye weeks from the Sleeper schedule API (canceled games ignored).
4. `espn_ranks.attach_ranks(board, live_espn_ranks, fp_ranks)` joins ESPN, Berry and FantasyPros ranks onto the board. `fp_ranks` comes from `fantasypros.fetch_consensus_rankings` (the 100+ expert consensus, `scoring_code_for` picks PPR/HALF/STD from the league's reception value; fields `fp_rank`, `fp_rank_std`, `fp_tier`). `sleeper_rank` is the board's own VOR order. `consensus` is the **market** view, the mean of FP, ESPN and Berry (the board's order is not a vote), and `rank_spread`/`disagreement` (>= 15) measure how far the board's order sits from any market rank, which is what the SPLIT flag shows. Live ESPN ranks win over the committed `espn_rankings.json` snapshot; `berry_rankings.json` is a hand-maintained snapshot.
5. `draft_app.load_board` (cached `FEED_CACHE_SECONDS` = 30 min, keyed on scoring key, team count, the scoring/starters dicts passed as sorted tuples, and a use-FantasyPros flag) returns `(board, projection_note)`; it calls the equally cached `load_fantasypros` and `load_espn`. Each feed degrades independently (per-position tolerance inside `fetch_all`, retries on 429/5xx for FantasyPros; the feed loaders return `{"ok", "data"|"error"}` instead of raising so outages are cached too). `load_board` returns `(board, note, degraded)`. All three loaders take a `retry_bucket` argument that is 0 while healthy and `time // DEGRADED_RETRY_SECONDS` once `st.session_state.board_degraded` is set, so a missing feed is retried every 5 minutes instead of on every rerun (never raise out of a cached loader to force a retry: that rebuilds the board on every click). "Refresh projections" (in the board expander) clears all three. ESPN needs no key; FantasyPros needs `FANTASYPROS_API_KEY`. The app dedupes by `player_key = "{name}|{team}|{position}"`. A failure of the board load itself renders an error with Retry/Disconnect buttons and `st.stop()`s.

Roster logic goes through `roster_slots.allocate_slots(my_roster, starters)`, which fills dedicated slots with the best VOR first and spills leftovers into flex slots per `FLEX_ELIGIBILITY`. Its `SlotAllocation` (`slots`, `bench`, `needs`, `filled`, `total`, `missing`) drives the sidebar roster, Still Need, Strengths, the bench count, the recommendation, and `grader.grade_draft(my_roster, starters)`.

The recommendation comes from `recommend.rank_candidates(available, needs, roster_size, total_picks, roster_counts, picks_made, gap, reach_gap)`, which returns a scored shortlist (`player`, `adjusted`, `vor`, `lookahead`, `fills_need`, `reach`, `back`, `later`, `mode` in {"value", "now", "reach"}); `recommend_pick` is a thin wrapper returning the top entry plus a one-line reason. The top of Draft mode is deliberately three things: a two-line status strip (round, pick, roster, your-pick-in, Sleeper heartbeat; sync controls on the right), one bordered recommendation card (mode pill, name and tags, two-line reason, Draft / He-got-taken buttons, then the next three candidates with their odds), and two collapsed expanders ("If you wait" holding Cost of Waiting and the likely-gone chips; "Manual entry" holding Quick Entry and Undo while Sleeper sync is on). Board details and Refresh projections live in the sidebar under the league. Resist adding more blocks above the board; the clutter is what the owner complained about.

Streamlit columns keep their proportions down to 640px, so a half-screen window (the draft-room-beside-the-app case) gets the **compact layout**. It switches on by itself below `COMPACT_BELOW_PX` (1100) using the browser width reported by `streamlit_js_eval` (the `streamlit-js-eval` package; returns None on the first run, then reruns with the value, so a headless AppTest always sees the wide layout). The sidebar "Layout" radio (`layout_pref`: Auto / Wide / Compact, also `?compact=1|0`) overrides it. In compact mode: the status strip stacks its controls and adds a Still-need line, the recommendation card drops the photo and uses half-width buttons, Cost of Waiting is 2x2, and each board row is one cell (rank, name, tags, one meta line) plus Mine/Taken. Buttons are `white-space:nowrap` everywhere so they never wrap letter by letter. Verified at 760px wide. Candidates exclude players at a `POSITION_CAPS` limit, players with an `EXCLUDED_STATUSES` injury status (IR/PUP/Sus/...; `is_unavailable`), a second QB or TE before `SECOND_QB_TE_ROUND` (11; a backup never starts, so raw VOR overrates him against RB/WR depth), and K/DEF until `late_window_open`: the final `LATE_ROUND_WINDOW` (3) picks, or within `EXTENDED_LATE_WINDOW` (6) once `LATE_RUN_STARTED` (2) of them have been drafted league-wide (`drafted_positions`, a Counter the app builds from `draft_info["pick_positions"]`; the 2026 room started its K/DEF run at pick 105, two rounds early). When open, an unfilled slot gets `LATE_NEED_BONUS`. The last-resort fallback relaxes caps, then timing, but never admits K/DEF early or injured players. Without pick info the score is VOR plus `NEED_BONUS` (30) when the player fills an open dedicated slot or `FLEX_NEED_BONUS` (15) when he only fills a flex slot (`need_kind`); the smaller flex bonus keeps a third RB from taking the FLEX while WR2 sits open (a rehearsal showed exactly that, and the simulator priced the change at ~2 lineup points, i.e. noise). After ranking, a same-position tie-break (`SAME_POSITION_TIEBREAK` = 10 adjusted points) puts the higher-VOR player first when a same-position rival outscores him only via survival-scaled bonuses, which are double-counted noise between two players filling the same slot (the live-draft Pickens-over-Rice bug). The panel also lists "Close in value" players within `CLOSE_VOR` of the pick, best at each position, with the slot each would fill. With `picks_made` and `gap` (other teams' picks before my next turn) it becomes a one-step lookahead: VOR plus `expected_best_vor(available, None, ...)` with the candidate removed, i.e. this pick plus the best pick I can expect next turn. Survival odds come from `survival_for(p, picks_made, gap)`: a normal model of draft slot around Sleeper ADP whose spread is the FantasyPros expert rank spread (`FP_STD_SCALE * fp_rank_std`, floor `FP_STD_FLOOR`; measured ADP dispersion ran ~1.0-1.4x the expert spread) when known, else `max(ADP_SD_FLOOR, ADP_SD_SCALE * sqrt(adp))`. Always call `survival_for(p, picks_made, gap, demand)` with the player dict; `survival_probability` is the bare formula. `demand` is an optional callable `gap -> {position: hazard multiplier}` from `opponents.demand_multipliers`: it reads each opponent's roster from the synced picks (`draft_info["pick_positions"]`, `draft_info["draft_meta"]`), works out which teams pick in the window (`upcoming_rosters`, snake/linear), scores each team's appetite for a position (`demand_factor`: open slot 1.0, flex-only 0.6, bench-only 0.3, at cap or early K/DEF 0.05), and returns the window's average relative to the league average, clamped to 0.3-2.5. Survival is raised to that power. It is empty (neutral) until Sleeper publishes the draft order. The app builds `demand` once per render (memoised per gap) and threads it through `rank_candidates`, `cost_of_waiting`, `likely_gone` and the row odds; the "If you wait" drawer shows the multipliers as chips. No ADP means safe; Sleeper's `999` undrafted sentinel is mapped to None in `draft_board`. The same model drives `likely_gone` (chip row under the stat cards) and `cost_of_waiting` (the per-position panel that replaced the tier-count scarcity panel). The app derives two numbers from `draft_info["next"]`: `reach` = `picks_until_mine` (other teams' picks before I am on the clock, 0 on my turn) and `horizon` = `picks_until_following` (picks between my next turn and the one after). Between turns, candidates are limited to players with at least `MIN_REACH_PROBABILITY` of reaching my pick (`reaches_me`), and the lookahead is evaluated from my pick forward over `horizon`; on the clock everyone is a candidate. `likely_gone` uses `reach` (or `horizon` on my turn). Before Sleeper publishes the draft order `horizon` is None (pure-VOR recommendation) and the panels assume one round (`num_teams`). A `horizon` of 0 is real (back-to-back picks at the turn, or your last pick) and must never be padded: `likely_gone` is empty, `cost_of_waiting` reports 0, and the recommendation is pure VOR.

Simulation findings (2026-08-21, 1,000+ drafts vs ADP-with-noise opponents): the lookahead beats ADP drafting by ~70 lineup points and the no-market fallback by ~7; `NEED_BONUS` 25-35 is the sweet spot (swept); `MARKET_CANDIDATES=40` never binds; a bye-week penalty, a last-in-tier bonus, and a 2-pick K/DEF window all *lose* points, so do not add them to the score. Post-draft (2026-08-23, 36 paired drafts): replacing the player-level need-urgency scaling with position-level urgency (bonus scaled by how much the slot's filler degrades if you wait) lost ~4.6 lineup points because a deep flat WR pool zeroes the bonus and the recommender drifts into pure-VOR RB stacking; it was reverted. The shipped package (same-position tie-break + run-aware K/DEF window) gained +1.9 over the draft-day code. The RB-heavy top of the board is a projection call (top RB VOR 173 vs WR 128), not a bug; the SPLIT flag is the right treatment. Players with no ADP are skipped inside `expected_best_vor` rather than treated as certain to be available.

The board hides K/DEF from the "All" list outside the late window (`LATE_ONLY_POSITIONS`), matching the recommender. Under VOR sort, tier headers show the count left in the tier (over everything available, not just visible rows) and the VOR drop to the next tier, and the last available player of a tier carries a LAST IN TIER chip. Row meta is two lines: value plus colored survival odds and split flags, then bye and market ranks. "Board #" is the board's own VOR order (formerly mislabeled Sleeper #) and only shows under non-VOR sorts. Auto-sync polls every `SYNC_INTERVAL` (15s) before the draft, `SYNC_INTERVAL_DRAFTING` (5s) while picks are being made, and `SYNC_INTERVAL_NEAR_TURN` (3s) within `NEAR_TURN_PICKS` of my turn; in a bot mock draft picks land faster than any of these, so a few seconds of staleness there is expected and does not happen with humans on a 2-minute clock. The recommendation card always leads with the here-and-now pick: `recommend.headline_and_plan` ranks with `reach_gap=0` (what to take if on the clock this instant) for the headline and, between turns, separately ranks the fallback plan through the `HEADLINE_REACH` gate (65%; the looser 25% candidate gate reached the owner 6/14 times in a rehearsal, 65% reached 9/14). Between turns the pill reads "BEST NOW · N% TO REACH YOU" (green at or above the gate, amber below), the second line is "N picks before you're up. If he's gone: X (pos, VOR) · N% to reach you", and the Next-best chips show reach odds instead of back odds. The owner asked for exactly this after a mock where the old layout headlined the safe-for-later player (Dak) over the best player on the board (Egbuka); the plan must stay a muted reminder, never the headline. "Holding off on X: reason" (`held_reason`) is appended whenever a higher-VOR healthy player is being skipped by a rule.

Live pick sync: `sync_picks_from_sleeper` in `draft_app.py` fetches the draft (`active_draft_id()`: the league's draft, or `st.session_state.rehearsal_draft_id` when the owner pasted a mock-draft link into the sidebar's "Rehearse with a mock draft" expander) and its picks through `sleeper_league`. The owner's roster id comes from the published draft order (`my_roster_id_from_draft`, the only option in a mock draft) with league rosters as the pre-order fallback, then `pick_sync.apply_picks` maps Sleeper `player_id`s onto the board and splits taken vs mine. The manual "Sync picks" button only sets `sync_requested` via `on_click`; the sync itself runs at module level before any widget renders, so it never resets widget state. `draft_info` carries `status`, `has_order`, `picks`, `next`, `unmatched`, and `unmatched_names` (rendered as one-click Taken buttons); a change in status or the draft order appearing counts as a change so the page refreshes when the draft starts. `last_sync_at` drives the heartbeat (orange past `SYNC_STALE_SECONDS`). Auto-sync defaults on for a connected draft (`auto_sync_pref`). `roster_id` is authoritative when present (a commissioner can click for an absent manager), `picked_by` is the fallback. The synced snapshot lives in `st.session_state.synced_taken` / `synced_mine` and is *replaced* on every sync so reversed picks disappear; manual marks live in `drafted` / `my_roster` and are layered on top (a manual "Mine" on a player Sleeper says someone else took is dropped). Everything downstream reads the effective locals `drafted_keys` and `my_roster`, not the raw session keys. `pick_sync.next_pick_info` handles snake and linear orders (returns None for third-round-reversal or auction, or until Sleeper publishes `draft_order`) and reports both `picks_until_mine` and `picks_until_following` (the gap to the turn after that). Auto-sync is an `st.fragment(run_every=SYNC_INTERVAL)` that calls `st.rerun(scope="app")` only when the snapshot changed.

`player_key` is the universal player identity across session state. Players are plain dicts enriched in place at each stage; `categories.py` functions also mutate board dicts in place, and since those dicts live inside `st.cache_data`, the mutations persist across reruns. That in-place style predates the immutability rule in the owner's global coding-style rules; the modules written since (`lineup`, `weekly_board`, `matchups`, `dvp`, `projection_log`, `manual_draft`) return new dicts, and new code should too.

`news.py` holds the three Claude calls, all routed through `create_message(model, effort, max_tokens, prompt, search_uses)`, which shapes the request for the configured model: current-generation models (Opus 5, Sonnet 5, Fable 5, the 4.6+ family, see `CURRENT_GEN_PREFIXES`) get the `web_search_20260209` tool and `output_config.effort`; older models (Haiku 4.5) get `web_search_20250305` and no effort. Opus 5 and Fable 5 requests go through `client().beta.messages.create` with the `server-side-fallback-2026-06-01` beta and `fallbacks=[{"model": "claude-opus-4-8"}]` so a safety refusal reruns on the fallback; `response_text` still checks `stop_reason == "refusal"`. Source links come from `collect_sources`, which reads both text-block citations and `web_search_tool_result` blocks (the newer tool reports URLs there). The analyst prompt is built by the pure `build_analyst_prompt` (tested) and receives the top `BOARD_ROWS_FOR_ANALYST` available players with per-source points, VOR, tier, bye and injury status, the open starting slots, and `scoring.scoring_summary` of the league rules; it is told to treat those numbers as ground truth. Measured on 2026-08-21: analyst ~18s without search, 40-120s with; Sonnet 5 was not faster and misread the scoring, so Opus 5 stays the default. The Anthropic client is created lazily in `client()` so importing `news` never needs a key.

Other modules: `grader.py` scores the roster (40% avg VOR clamped to [0, `FULL_MARKS_AVG_VOR` = 20], 35% slots filled, 25% positional balance; a complete roster with no value is a 60/D). `categories.py` provides the sleeper/rookie/boom/floor queries for the Insights tabs.

### Rankings JSON files

Both live in `src/` and are read only by `espn_ranks.py`, which caches them in module globals, so edits require a process restart.

- `espn_rankings.json`: 300 records `{espn_rank, position, pos_rank, name, team}`, generated by `extract_espn.py` from a PDF.
- `berry_rankings.json`: 240 records `{berry_rank, tier, name, position, team}`, hand-maintained, no generator script.

Both JSONs use `"DST"` for defenses; the board uses `"DEF"`. Matching is by name so this does not break the join directly.

## Manual drafts (Yahoo, ESPN, anything the app cannot sync)

A league config with `"draft_id": null`, `"platform": "Yahoo"` and `"manual_draft": {"teams": N, "rounds": R, "slots": {"Marc": 4, "Wife": 1}}` puts the app in manual mode (`src/manual_draft.py`). There is no pick sync: the owner marks every pick in the room in order (Quick Entry, Enter = taken by someone else), and the ordered `pick_log` *is* the draft. `manual_draft.draft_info` turns the log plus the snake order into the same `draft_info` payload `sync_picks_from_sleeper` would have produced (pick count, `next_pick_info` for the active team, `pick_positions` by snake slot for the opponent-needs model), so the status strip, lookahead, K/DEF run rule and reach odds all work unchanged; the odds lag whenever the log falls behind the room. `slots` can list several household teams: the sidebar "Drafting for" radio (`team_pref`, `switch_team`) swaps which team's roster is `my_roster` while the others live in `st.session_state.rosters`; marking a pick for one team counts it as gone for the others. `draft_state.save_state` persists `rosters` and `pick_log` keyed by `manual:<league_id>`, and the Draft-slots expander rewrites `manual_draft.slots` through `save_league`. Lineups without K/DEF need no special handling: `fills_need` keeps those positions out of the candidates and off the All list. Scoring for such a league is hand-translated into Sleeper's stat keys (the 2026 Yahoo config used `rec`, `pass_yd 0.04`, `pass_td 6`, `kr_td`/`pr_td`, `fum_lost`). Known gap: with a 90-second clock the hand log missed 15 of 150 picks and mis-assigned one; a paste-to-resync box is the planned fix (`~/.claude/plans/post-draft-updates.md`).

## Start/Sit mode

The second radio option (`app_mode`, hidden while a synced draft is live). It never touches draft-mode state: its own keys are `ss_username`, `ss_user_id`, `ss_league_options` (`{league_id: Sleeper league payload}`), `ss_league_pref`, `ss_week_pref`, `ss_error`, `ss_degraded`, and the last username/league are remembered in the gitignored `.start_sit.json` (`load_start_sit_prefs`/`save_start_sit_prefs`). Any Sleeper username works, so the household's other leagues are one lookup away. Data flow: `sleeper_league.get_nfl_state` + `lineup_week` pick the default week; `load_lineup_context(league_id)` fetches the league (its `roster_positions` and `scoring_settings`) and rosters, `find_my_roster` picks the owner's; `load_weekly_pool(week, scoring_items, use_fantasypros, retry_bucket)` mirrors `load_board` with the week as a cache key (`load_weekly_fantasypros` = `fantasypros.fetch_all(..., week=)` + `fetch_weekly_rankings`, `load_weekly_espn` = `espn_projections.fetch_all(season, week=)`), and `weekly_board.build_weekly_pool` runs `draft_board.fetch_position(..., week=week)` per position so the per-stat median blend, `scoring.score_stats` and the K/DEF preset totals are the draft board's code path (Sleeper's weekly URL is `/projections/nfl/{season}/{week}`; `gp` is 1 so the threshold-bonus estimate becomes a single-game tail). `attach_weekly_ranks` joins the FantasyPros weekly consensus by `match_key` (`fp_week_rank`, `fp_week_pos_rank`, `fp_week_rank_std`, `fp_grade`, `fp_opponent`; the grade and opponent are undocumented fields the API returns only for per-position requests, which is why `fetch_weekly_rankings` makes six per-position calls instead of one `ALL` call). `roster_rows` gives every rostered player a row in roster order, scoring 0 with `reason` "bye" or "no projection" when the weekly pool lacks him (a player missing from both feeds and the season board renders as "Unknown <id>"). The pure decisions live in `lineup.py`: `current_lineup` zips Sleeper's `starters` (in `roster_positions` order, "0" = empty) with the modelled slots, `optimal_lineup` is `allocate_slots(startable(rows), starters, key="points")` padded with None for slots nobody can fill, `can_play`/`startable` drop `SIT_STATUSES` (Out, Doubtful, and the draft's IR/PUP/... set) and any `reason` but keep Questionable, `expected_points` counts only players who can play (an Out starter still carries FantasyPros/ESPN points, so the Current column shows both numbers and the swap gain is measured against zero for him), and `lineup_diff` pairs incoming with outgoing players (same position first, then anyone eligible for the slot), carries `out_reason`, and flags deltas under `COIN_FLIP_POINTS` (1.5). ESPN weekly blocks are `statSplitTypeId 1` with `scoringPeriodId == week` (`_projection_block`); the season block stays split 0. Weekly projections miss by 30-40% per player, so the page shows the FantasyPros spread and labels small swaps as coin flips rather than pretending to precision. The legacy ESPN in-season tools (`waivers.py`, `connect.py`, `test_cookies.py`, `espn-api`) were removed on 2026-09-09.

**Matchup layer** (`src/matchups.py`, `src/dvp.py`; sidebar toggle "Adjust for matchups", `ss_adjust_pref`, default on). nflverse's free schedule (`matchups.SCHEDULE_URL`, stdlib `csv`, no pandas) gives every game's Vegas spread and total (positive `spread_line` = home favored; lines are posted only ~7 weeks ahead), home/away/neutral and the roof; `team_context(games, week)` turns that into per-team implied totals (home = total/2 + spread/2). Team codes differ in exactly one place, nflverse `LA` = Sleeper `LAR` (`TEAM_CODES`); Sleeper `FA` has no game. Defense vs position has no free feed, so `dvp.py` computes it from nflverse weekly player stats: PPR points allowed per (defense, position, game) averaged and expressed relative to the league mean, rank 1 = stingiest; last season is the prior and the current season blends in with weight `n/(n+PRIOR_GAMES)` as its CSV appears (404 until then, noted on the page). `attach_matchup` returns a new pool with `matchup` (context, DvP factor/rank, factor, parts) and `adjusted_points = points x clamp(implied_term x dvp_term x site_term, 1 +/- CAP)` with `A_IMPLIED` 0.35 (term capped +/-10%), `B_DVP` 0.25, site 1.01/0.99/1.00 and `CAP` 0.12; K uses implied + site, DEF's implied term runs the other way (it faces the opposing offense). The feeds already price most of this, which is why the coefficients are small. `lineup.py` ranks by whichever `key` the app passes (`adjusted_points` when the toggle is on). Live on 2026-09-09 (week 1): all 32 teams had lines, factors ranged 0.88 (Judkins at a 16-point implied JAX) to 1.11 (Herbert home vs ARI, 28.5). Weather is roof-only (forecasts for future games are not free). Informational gaps (no lines yet, current-season stats unpublished) go into `notes`, not `problems`, so they never trigger the degraded retry cadence.

**Game-day lines** (`src/odds.py`, optional `ODDS_API_KEY`). nflverse's lines are a weekly snapshot; The Odds API's free tier (500 credits a month, `markets x regions` = 2 per call, key in the query string) lists every game the books have posted with every bookmaker's spread and total (all 240 remaining games on 2026-09-09, not just the current week, so `merge_lines` filtering by week matters; a `(home, away)` pair is unique within a season). `fetch_odds` never echoes the key (a `requests` exception's text carries the URL, so it reports the exception class instead) and turns the API's `error_code` (`INVALID_KEY`, `OUT_OF_USAGE_CREDITS` are 401, `EXCEEDED_FREQ_LIMIT` is 429) into an `OddsError`; `parse_events` takes the median across bookmakers and converts to nflverse's sign (`spread_line = -home_point`, positive = home favoured), mapping the API's "City Nickname" strings through the hardcoded `TEAM_NAMES`; `merge_lines(games, lines, week)` returns a new games list with `line_source` "live" or "nflverse", and `team_context` carries `line_source` per team. In the app, `load_live_odds(0)` is cached `ODDS_CACHE_SECONDS` (6h) and returns `{"ok", ...}` even for a refused call so quota exhaustion is not retried every rerun; it is always called with bucket 0 and its failures go to `notes` (a `problems` entry would set `ss_degraded` and refetch on the five-minute cadence, burning credits). `week_games(week)` is the one place the schedule and live lines meet: `load_weekly_pool` and `week_lines` (locks, the expander) both read it, so the chip ("imp 23.5 live"), the implied-totals table and the projection log's `implied` field all see the same number; the logged game-day implied total is the free tier's only route to a closing line. Without a key the note says "lines: nflverse weekly (set ODDS_API_KEY for game-day lines)".

**Waiver targets** (`src/waivers.py`, the "Waiver targets" expander at the bottom of Start/Sit, toggle `ss_waivers_pref`). Free agents are the weekly-pool rows nobody in the league holds (`rostered_ids` unions `players`, `reserve` and `taxi`, each of which Sleeper may send as null). The metric is `lineup_gain`: points of the best lineup with the candidate added minus without, computed twice: `week_gain` on the weekly rows with the page's key (`optimal_lineup`, so an Out player gains nothing) and `season_gain` on season rows with `allocate_slots` directly, ignoring injury (an IR stud is a keeper, not a hole). The season rows come from `load_season_board(league)`, which is `load_board` called with **this** league's scoring and starters; the draft-mode `board` belongs to whichever league is connected there (the Yahoo config in September 2026) and would score three of the four Sleeper leagues wrong. That build costs ~15s the first time per league, so it sits behind the toggle. `waiver_targets` splits "Add for the season" (`season_gain > 0`, never K/DEF) from "Streamers for week N" (`week_gain > 0` without a season gain, i.e. bye and injury fillers, plus every K/DEF); `drop_candidates` are my players outside both the weekly optimal and the season allocation, lowest season points first, no-projection players last, IR never. `waiver_settings` maps `waiver_type` 0/1/2 to rolling / reverse standings / FAAB and `faab_left` reads `roster.settings.waiver_budget_used`; the weekday index is deliberately not printed because Sleeper's `waiver_day_of_week` base is unverified. Sleeper's trending adds (`sleeper_league.get_trending_adds`, `load_trending` cached an hour) show as an "N adds/24h" chip, a market signal like ADP was on draft day. A third list, "Depth upgrades", covers the case where the lineup is already set: free agents worth more over the season than my least valuable droppable player, compared by the season board's `vor` (raw season points would rank a QB3 above a TE2 in a one-QB league), never K/DEF, never IR/PUP stashes on either side (`recommend.is_unavailable` is the one definition of "long-term out" for candidates and drops alike); drop candidates sort by the same value. With `current` passed, this week's gains go through `reachable_lineup`, so a free agent whose game already kicked off gains nothing and a locked starter keeps his slot; the page stamps locks on the free agents too. Every gain assumes a free roster spot. `weekly_board.assemble_pool` is the shared build (pool -> weekly ranks -> matchup) used by `load_weekly_pool` and the CLI report.

**Tuesday report** (`src/waiver_report.py`): `.venv/bin/python src/waiver_report.py --user magoo82 --user amcgough13 [--week N] [--limit 8]` prints one block per league of each user (waivers and FAAB, kickoff-aware lineup swaps, season adds, streamers, depth upgrades, drop candidates) using the modules directly, `SharedFeeds` fetching every league-independent feed once (a missing feed becomes a note, never fatal), one weekly pool per distinct scoring and one season board per league config; a league that fails prints its error and the report continues; exit code 1 if anything failed. `format_league_report` and the `format_*` helpers are pure and tested. Ran in ~22s for four leagues on 2026-09-09. It is the entry point for a cloud routine (`/schedule`, runs unattended; the CLI's `CronCreate` is session-local and the desktop scheduled task needs the desktop app), whose environment needs `FANTASYPROS_API_KEY` and `ODDS_API_KEY` as secrets for the full blend.

**Kickoff locks.** Sleeper freezes a player once his game starts, so the page must never recommend moving one. nflverse's `gameday`/`gametime` are US/Eastern; `matchups.kickoff_time` turns a team context (or a row's `matchup`, which carries the same fields) into an aware `ET` datetime, `locked_teams(context, now)` is the set whose kickoff has passed, and `next_kickoffs` lists the games still to start (deduped by team pair, since each game appears twice in the context and a neutral-site game has no home side). The page stamps `locked` onto the roster rows with `lineup.mark_locked` **before** building `rows_by_id` and `current`, so every dict downstream carries the flag. `lineup.reachable_lineup(rows, current, starters, key)` is what the owner can still do: locked starters stay in the exact slot they occupy (a locked RB in FLEX stays in FLEX; a locked Out starter stays too), locked bench players never enter, and the open slot counts go through `optimal_lineup` over the unlocked rows. Swaps come from `lineup_diff(current, reachable)`; `lineup_diff` also drops equal-point reshuffles when the outgoing player can play (ties, or a lock shuffling players around, produced `+0.0` swaps the coin-flip test never flagged). The unconstrained `optimal_lineup` is still computed so `render_missed` can say what the locks cost ("Missed: Stevenson locked out of the lineup; would have added 2.6", measured with `expected_points` on both sides so a locked Out starter's listed points do not inflate it). `render_lock_status` prints one line limited to the owner's own teams ("Locked: NE, SEA (kicked off Wed 8:20 pm ET) · Next kickoff: Thu 8:35 pm ET, LAR vs SF (McCaffrey starting)"; `matchups.game_label` reads "SF at LAR" for a home game and "vs" only on a neutral site), `render_swap` appends the deadline from `lineup.swap_deadline` (the earlier of the two players' kickoffs) through `lineup.deadline_status` (hours rounded down, red inside `KICKOFF_SOON_HOURS`), rows show a LOCKED chip, a fully locked week reads "Week N is locked" instead of "already optimal", the stuck-starter warning separates locked players (nothing to do) from replaceable ones, and `lineup.missed_players` tells a player locked on the bench from a free one blocked by a locked starter holding his slot. `reachable_lineup` feeds the allocator the current starters before the bench, so a tie never recommends churn (the allocator's sort is stable). The `lock_watch` fragment (`LOCK_WATCH_SECONDS`) reruns the page when a kickoff passes, so a page left open across the 1:00 pm wave locks on time; when nflverse is unreachable the page says lock status is off rather than silently locking nobody. A future week locks nothing; a past week locks everything. A mid-week trade follows Sleeper's current `team` at pool-fetch time (30-minute cache). `week_lines(week)` in `draft_app.py` is the one place the render block reads the week's context. The Wednesday-night lesson behind this: the page recommended Stevenson into the FLEX after NE-SEA had kicked off.

**Projection log** (`src/projection_log.py`, `.projection_log.jsonl` at the repo root, gitignored; `PROJECTION_LOG_FILE` overrides the path so headless runs never touch it). When the Start/Sit page renders it appends the whole weekly pool once per (season, week, league): `{"kind": "projection", ..., points_by_source, blend, adjusted, fp_week_rank, implied, dvp_factor, site}` followed by a `{"kind": "logged", "what": "projection", coefficients}` marker (the marker is the idempotency check; `ss_logged` avoids re-reading the file every rerun). The "Matchups and accuracy" expander's "Record week N actuals" button fetches Sleeper's real weekly stats (`api.sleeper.com/stats/nfl/{season}/{week}`, same player ids as projections) scored with the league rules and `score_stats(..., estimate_bonuses=False)` (a game's threshold bonuses either happened, and Sleeper reports them as their own keys, or did not; the season estimator would add half a bonus to every 100-yard game). `accuracy_report` joins projections to actuals and reports n, MAE and bias per source (sleeper/fp/espn/blend/adjusted), overall and per position, plus inverse-MAE feed weights once every feed has `MIN_FEED_SAMPLE` (50) player-weeks. The calibration step is deliberately not automated yet: after ~300 pairs, regress `actual/blend - 1` on `implied/avg - 1`, `dvp - 1` and site with `statistics.linear_regression`, adopt a slope only if its sign agrees and |slope| < 1, and default the toggle off if `adjusted` MAE exceeds `blend` MAE.

## Things that will trip you up

- **Season year is hardcoded** as `SEASON` in both `draft_board.py` (projections, byes) and `draft_app.py` (which Sleeper leagues to list). Both rankings JSONs are preseason snapshots that must be regenerated each year.
- **Streamlit widget keys**: Streamlit drops a keyed widget's session-state entry as soon as that widget stops rendering, and a mid-render `st.rerun()` skips every widget below it. So: every preference lives in a non-widget `*_pref` key bound via `index=`/`value=` + `on_change` (`scoring_pref`, `league_size_pref`, `sort_pref`, `auto_sync_pref`), and actions that need a fresh run set a flag in `on_click` and act at the top of the script (`sync_requested`). Never call `st.rerun()` from the middle of the page except in the fragment.
- **Quick entry is an `st.form`**: the first `form_submit_button` (Taken) is what Enter triggers; both submit buttons use `on_click=quick_mark` and read `st.session_state.quick_entry`, which is set before callbacks run. Manual marks record `last_mark` for the Undo button; synced marks are not undoable (Sleeper is the truth for those). Manual marks are persisted to `.draft_state.json` (gitignored) keyed by `draft_id` via `draft_state.save_state` on every mark/undo/reset and restored once per session after the board is built, so a browser refresh or laptop sleep does not lose them; synced picks are simply re-pulled from Sleeper. The app never submits picks to Sleeper (the public API is read-only); the owner picks in the Sleeper app and auto-sync reflects it.
- **Defenses never match the rankings files.** Sleeper names them like "Los Angeles Rams" while the JSONs use "Rams D/ST"-style names, so DEF rows have no ESPN/Berry/consensus rank. (`fetch_position` also computes an unused `"{team} DST"` fallback name; it is dead code, not a bug in practice.)
- **Theme and toolbar** come from `.streamlit/config.toml` (dark base, `#00e0a4` primary, `toolbarMode = "minimal"`); it is read at server start, so restart after editing it. Component styling beyond that is the inline CSS block in `draft_app.py` (`.badge`/`.chip` are `inline-block; white-space:nowrap` so tags never break mid-chip; primary buttons are filled green).
- The board is fetched from Sleeper in both modes: the sidebar player search needs it, and Start/Sit uses it as the season index (name, team, bye) for rostered players the weekly feeds omit.
- Round/pick math assumes every pick in the league is marked as drafted, not just yours.
